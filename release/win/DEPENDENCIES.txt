Licence compatibility
--------------------------------------------------------------------------

  OpenSSL 3.x            Apache-2.0   <-- incompatible with GPLv2, fine under v3
  MariaDB Connector/C    LGPL-2.1

  SQLite                 Public Domain
  libssh2                BSD-3-Clause
  zlib / lz4             zlib / BSD-2-Clause

OpenSSL is statically linked into the exe, so its licence cannot be avoided by
not shipping a DLL. Apache-2.0's patent-termination clause is incompatible with
GPLv2 but compatible with GPLv3 -- which is why GPLv2 was not an option here.

The Oracle Instant Client SDK is proprietary and is NOT distributed with this
repository or with the installer. It is used only at compile time, on the
machine of whoever chooses to build the optional Oracle driver.

--------------------------------------------------------------------------
SwiftSQL.exe — self-contained, no C++ runtime required
--------------------------------------------------------------------------
Built with the STATIC MSVC runtime (/MT) and static vcpkg libraries, so it
needs NO Visual C++ Redistributable — vcruntime140/msvcp140 are baked in.
`dumpbin /dependents SwiftSQL.exe` lists only Windows system DLLs:

  dbghelp, bcrypt, Secur32, CRYPT32, ODBC32, IMM32, KERNEL32, USER32, GDI32,
  COMDLG32, WINSPOOL.DRV, SHELL32, SHLWAPI, COMCTL32, ole32, OLEAUT32, RPCRT4,
  ADVAPI32, WS2_32, OLEACC, UxTheme, dwmapi, MSIMG32

(23 imports, all shipped with Windows. Verified against the 1.1.20 build.)

All database drivers except Oracle are statically linked into the exe
(MySQL/MariaDB, PostgreSQL libpq, SQLite, SSH tunnel libssh2, OpenSSL) — no
app-local DLLs required for them.

SQL Server uses the Windows ODBC subsystem (ODBC32.dll, system-provided). The
"ODBC Driver 17 for SQL Server" must be installed separately by the user if
they connect to SQL Server; it is not bundled here.

--------------------------------------------------------------------------
Oracle — NOT bundled
--------------------------------------------------------------------------
The Oracle Instant Client is intentionally NOT shipped in this installer (it is
large and would drag in a Visual C++ 2005 runtime dependency via MSVCR80.dll).
The app still supports Oracle / 达梦: a user who needs it drops a 64-bit oci.dll
next to SwiftSQL.exe, or points the in-app OCI path at their Oracle client.

--------------------------------------------------------------------------
Visual C++ runtime — NOT bundled, and not needed
--------------------------------------------------------------------------
The installer ships no VC++ Redistributable. There is nothing for it to fix:
the dependency list above contains no vcruntime140.dll, no msvcp140.dll and no
api-ms-win-crt-* — the CRT (including the Universal CRT) is linked into the exe
at link time by /MT, so "the C++ runtime is missing" is not a state this build
can be in.

Earlier releases bundled VC_redist.x64.exe "as a safeguard". It was 25 MB of an
installer that is otherwise 7 MB, guarding a failure mode that cannot occur, and
it was removed in 1.1.20 (installer: 29.9 MB -> 7.3 MB).

That removal depends on the build staying on the static CRT, which is decided in
a different file (CMAKE_MSVC_RUNTIME_LIBRARY in CMakeLists.txt). To keep the two
in sync, release\win\build_installer.bat runs dumpbin on the staged exe before
packaging and ABORTS if it finds a dynamic-CRT import. Switching to /MD without
restoring the redistributable therefore fails at packaging time, rather than
silently shipping a package that dies on a clean machine.

--------------------------------------------------------------------------
Minimum operating system
--------------------------------------------------------------------------
Windows 10 x64 or later (the installer enforces MinVersion=10.0).

This is a toolchain constraint, not a policy: the exe is built with the MSVC
14.5x toolset, and Microsoft dropped Windows 7/8 support in VS 2022 17.10
(toolset 14.40). Because the CRT is static, those Win10-only imports are baked
into the exe — a Windows 7 install would complete and then fail to launch, so
the installer refuses up front instead.

--------------------------------------------------------------------------
User-data footprint (for reference / uninstall)
--------------------------------------------------------------------------
All per-user data lives in a single directory:  %APPDATA%\SwiftSQL\
  settings.ini            UI settings + language preference
  connections (+ secrets) saved connections and encrypted passwords
  scripts_index.ini, *.sql saved SQL scripts
  favorites, automation jobs
  crash.log

The uninstaller removes program files automatically and offers (default: No) to
also delete this data directory.
